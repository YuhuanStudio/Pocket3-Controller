## English

**Release-note draft for build 21, compared with published beta 1 build 9.** Beta 2 has not been published by this draft; the existing [beta 1 release](https://github.com/YuhuanStudio/Pocket3-Controller/releases/tag/v0.0.1-beta.1) remains unchanged.

### AI camera adjustments have explicit roles

With Apple selected and camera-control access enabled, a downloaded MLX model now handles the camera tool loop. The App then obtains a newer frame for Apple to answer from. Apple observe-only mode still works without MLX; selecting MLX uses MLX for both control and the answer. Models are never downloaded automatically, and the interface explains when the controller model is missing.

The interface and result metadata identify the controller, answer model and App frame refresh separately. An App refresh is not counted as another model tool call. A real-device task using one zoom adjustment completed this mixed-model flow in 38.039 seconds; this is evidence for that task, not a guarantee for every request.

### Cancelling zoom now holds the camera's current zoom

Cancelling an in-flight zoom request now waits for a same-connection hold instead of merely clearing the App's moving state while the device continues towards the target. An expired settling deadline uses the same cleanup. A successful hold does not turn the original unfinished zoom into a successful adjustment; an unconfirmed hold blocks further zoom and pan/tilt commands until resolved.

On build 20, a real external MCP cancellation held raw zoom at 200 during a 100→400 request. Independent readbacks stayed stable for 1.090 seconds, without the client sending Stop, and the helper still served its six tools. Timeout cleanup has a deterministic fake-device regression; it has not been induced and verified on the real camera. These readbacks are not calibrated magnification or mechanical braking measurements.

### Active capture can keep working without keeping the display lit

Active capture now holds a scoped macOS activity that prevents idle system sleep. It does not request that the display stay on or change system sleep preferences. Pause, stop, failure and device disconnection release the activity; a new capture session receives its own activity. Explicit system sleep still follows the existing Stop/suspend path.

The activity's acquisition, release and reconnection were checked on the real App while USB preview continued. Physical display-off, locked-session and remote-desktop disconnection behaviour still need separate verification. This remains a logged-in user App, not a service available before login.

### The Yun interface is more consistent across languages

Engine cards, control rows, long MCP paths and settings labels now align more consistently at compact and larger window sizes. Camera and microphone icons align with their labels, and audio feedback and action history use the correct translated descriptions. English, Traditional Chinese and Simplified Chinese received visual review. Documentation includes complete guides and UI-only screenshots without camera photographs.

### Offline development checks

The finite USB validation sequence now ends after an unconfirmed target, hold or return, retaining a partial report. A failed or cancelled report cannot unlock movement. Read-only imported-image diagnostics also gain typed count, point and presence results with range validation; this is an evaluation API, not a completed subject-tracking interface. New hardware validation remains pending.

### Evidence and remaining limits

- Build 21's Release suite contains 495 tests: 492 passed and three opt-in tests were skipped. This is the recorded suite result, not a new complete beta 2 packaging gate.
- An isolated, re-signed build 9→17 copy completed actual Sparkle download, installation and relaunch, preserving preferences and producing a fresh IPC session. That test used a separate fixture identity/feed and no camera; it does not establish production-feed updating while capture is active.
- Native quick recenter/flip matching the camera's double/triple joystick press, tap-to-focus and reliable body-setting writes remain unfinished. The full-pair BLE recenter trial submitted its command but observed no motion or matching reply. Readable WB/AF/EV values do not establish that writes work; slow USB movement is not a substitute for native presets.
- UYVY/H.264 preview and 4K60 remain unavailable in the tested paths. An experimental compressed-output diagnostic does not make them usable preview modes. Proven NV12 modes remain the ordinary path; full physical range, speed calibration and experimental Roll are not fully verified.

See the [hardware evidence and limits](https://github.com/YuhuanStudio/Pocket3-Controller/blob/main/docs/HARDWARE_ACCEPTANCE.md) and [release procedure](https://github.com/YuhuanStudio/Pocket3-Controller/blob/main/docs/RELEASE.md) for the scope of each check.

### Installation and updating

Apple Silicon and macOS 27 remain required. The App name, bundle identifier, preferences, local model storage and MCP helper path inside the App remain unchanged. Keep the Mac on its existing network; normal USB control does not require joining the camera's Wi-Fi.

The Beta uses the existing local development signing identity and is **not notarised or Developer ID signed**. First-launch Gatekeeper behaviour on other Macs still requires verification. The signed beta 1 feed is already public; this draft does not publish a beta 2 archive, tag or feed entry. Production beta 1→beta 2 installation through the normal update UI remains a separate release check.

## 繁體中文

**以已發布 beta 1 build 9 為基準的 build 21 發行說明草稿。** 本文件不代表 beta 2 已發布；既有 [beta 1 發行版本](https://github.com/YuhuanStudio/Pocket3-Controller/releases/tag/v0.0.1-beta.1)保持不變。

### AI 相機調整有明確的模型分工

選擇 Apple 並允許 AI 控制相機時，現在由已下載的 MLX 模型執行相機工具流程，App 再取得較新的影格，交由 Apple 回答。Apple 的僅觀察模式仍不需要 MLX；選擇 MLX 時，則由 MLX 負責控制與回答。不會自動下載模型，缺少控制模型時介面會說明。

介面與結果 metadata 分別標示控制模型、回答模型及 App 的影格更新；App 更新影格不計為額外的模型工具呼叫。一次包含單筆縮放的真機任務已在38.039秒完成這個混合流程；這是該任務的證據，不保證每種要求都能完成。

### 取消縮放會保持相機當前的縮放位置

取消進行中的縮放要求，現在會等待同一連線上的保持操作，不會只清除 App 的移動狀態，讓機身繼續朝原目標前進。等待縮放穩定的期限耗盡時，也會執行相同清理。保持成功不會把原本未完成的縮放算作成功；保持未確認時，後續縮放及 pan/tilt 命令會被阻擋，直到問題解除。

build 20 的真實外部 MCP 測試，在100→400要求途中取消後保持於原始值200，獨立回讀穩定1.090秒，客戶端沒有另送 Stop，helper 仍能提供六個工具。正常逾時清理已有確定性的假裝置回歸測試，尚未在真機上製造並驗證逾時。上述讀回不是已校準倍率或機械煞停量測。

### 持續取像不需要要求螢幕常亮

取像期間現在持有有明確生命週期的 macOS activity，防止系統因閒置而睡眠；不要求顯示器常亮，也不修改系統睡眠偏好。暫停、停止、失敗或裝置斷線會釋放活動，新取像 session 會取得自己的活動。明確的系統睡眠仍走既有 Stop/suspend 流程。

已在真實 App 上核對活動的建立、釋放與重新連接，同時維持 USB 預覽。實際關閉顯示器、鎖定工作階段及遠端桌面斷線仍需分別驗證。App 仍是登入後的使用者程式，不是登入前可用的服務。

### Yun 介面在三種語言中更一致

引擎卡片、控制列、長 MCP 路徑及設定標籤，在精簡與較大視窗中有更一致的對齊。相機與麥克風圖示對齊文字，音訊提示及操作紀錄使用正確的本地化說明。英文、繁體中文及簡體中文均經視覺檢查；文件提供完整使用指南與不含相機照片的純 UI 截圖。

### 離線開發檢查

有限 USB 驗證序列在目標、保持或返回未確認時立即結束，保留部分報告；失敗或取消不能開啟移動權限。匯入圖片的只讀診斷也加入具型別與範圍驗證的計數、定位、存在性結果；這是評測 API，尚不是完整的主體追蹤介面。新硬體驗收仍待完成。

### 驗證與尚未完成的部分

- build 21 的 Release suite 共495項：492項通過，3項 opt-in 測試跳過。這是該次 suite 的紀錄，不代表新的 beta 2 完整打包 gate 已通過。
- 隔離且重新簽署的 build 9→17 副本已完成真正的 Sparkle 下載、安裝與重啟，保留偏好並建立新的 IPC session。測試使用獨立身分與 feed，沒有取像；不代表正式 feed 在取像中更新已完成驗收。
- 等同機身搖桿雙擊／三擊的原生快速回中與翻轉、點按對焦及可靠的機身設定寫入仍未完成。完整配對後的 BLE 回中試驗雖提交了命令，但沒有觀察到動作或匹配回覆。可讀取 WB/AF/EV 不代表可以寫入；慢速 USB 移動不當作原生預設的替代。
- 目前測試路徑仍未提供可用的 UYVY/H.264 預覽及4K60。實驗性壓縮輸出診斷不代表這些預覽模式已可用。日常路徑仍使用已驗證的 NV12 模式；完整物理範圍、速度校準及實驗性 Roll 尚未全數驗證。

各項驗證的範圍見[實機證據與限制](https://github.com/YuhuanStudio/Pocket3-Controller/blob/main/docs/HARDWARE_ACCEPTANCE.md)及[發行流程](https://github.com/YuhuanStudio/Pocket3-Controller/blob/main/docs/RELEASE.md)。

### 安裝與更新

仍需 Apple Silicon 與 macOS 27。App 名稱、bundle identifier、偏好、本機模型儲存位置及 App 內的 MCP helper 路徑保持不變。Mac 可維持原有網路，正常 USB 控制不需要加入相機 Wi-Fi。

此 Beta 沿用既有本機開發簽署身分，**尚未公證，也不是 Developer ID 簽署**。其他 Mac 的首次啟動與 Gatekeeper 體驗仍需驗證。已簽署的 beta 1 feed 已公開；本草稿不發布 beta 2 安裝包、tag 或 feed 項目。透過正式更新 UI 完成 beta 1→beta 2 安裝仍是獨立的發行驗收事項。

## 简体中文

**以已发布 beta 1 build 9 为基准的 build 21 发行说明草稿。** 本文件不代表 beta 2 已发布；现有 [beta 1 发行版本](https://github.com/YuhuanStudio/Pocket3-Controller/releases/tag/v0.0.1-beta.1)保持不变。

### AI 相机调整有明确的模型分工

选择 Apple 并允许 AI 控制相机时，现在由已下载的 MLX 模型执行相机工具流程，App 再获取较新的画面帧，交由 Apple 回答。Apple 的仅观察模式仍不需要 MLX；选择 MLX 时，则由 MLX 负责控制与回答。不会自动下载模型，缺少控制模型时界面会说明。

界面与结果 metadata 分别标示控制模型、回答模型及 App 的画面帧更新；App 更新画面帧不计为额外的模型工具调用。一次包含单笔缩放的真机任务已在38.039秒完成这个混合流程；这是该任务的证据，不保证每种请求都能完成。

### 取消缩放会保持相机当前的缩放位置

取消进行中的缩放请求，现在会等待同一连接上的保持操作，不会只清除 App 的移动状态，让机身继续朝原目标前进。等待缩放稳定的期限耗尽时，也会执行相同清理。保持成功不会把原本未完成的缩放算作成功；保持未确认时，后续缩放及 pan/tilt 命令会被阻止，直到问题解除。

build 20 的真实外部 MCP 测试，在100→400请求途中取消后保持于原始值200，独立读回稳定1.090秒，客户端没有另发 Stop，helper 仍能提供六个工具。正常超时清理已有确定性的模拟设备回归测试，尚未在真机上制造并验证超时。上述读回不是已校准倍率或机械刹停测量。

### 持续取像不需要要求屏幕常亮

取像期间现在持有生命周期明确的 macOS activity，防止系统因空闲而睡眠；不要求显示器常亮，也不修改系统睡眠偏好。暂停、停止、失败或设备断开会释放活动，新取像 session 会获取自己的活动。明确的系统睡眠仍走现有 Stop/suspend 流程。

已在真实 App 上核对活动的建立、释放与重新连接，同时维持 USB 预览。实际关闭显示器、锁定会话及远程桌面断线仍需分别验证。App 仍是登录后的用户程序，不是登录前可用的服务。

### Yun 界面在三种语言中更一致

引擎卡片、控制栏、长 MCP 路径及设置标签，在紧凑与较大窗口中有更一致的对齐。相机与麦克风图标对齐文字，音频提示及操作记录使用正确的本地化说明。英文、繁体中文及简体中文均经视觉检查；文档提供完整使用指南与不含相机照片的纯 UI 截图。

### 离线开发检查

有限 USB 验证序列在目标、保持或返回未确认时立即结束，保留部分报告；失败或取消不能开放移动权限。导入图片的只读诊断也加入具有类型与范围验证的计数、定位、存在性结果；这是评测 API，尚不是完整的主体跟踪界面。新硬件验收仍待完成。
