## English

**Release-note draft for development build 23, compared with published beta 1 build 9. Build 23 source includes the local media workspace, selected video frames, area selection and immutable result exports. The actual App smoke test and complete release gate are pending; the available offline media regression is development evidence only.** Beta 2 has not been published by this draft; the existing [beta 1 release](https://github.com/YuhuanStudio/Pocket3-Controller/releases/tag/v0.0.1-beta.1) remains unchanged.

### Work with local images, selected video frames and areas

Development build 23 extends build 22's image workspace. Choose **Media file**, then **Open media**, to select a readable local still image up to 8 MB or a local video with a video track. **Replace media** opens another file and clears the previous analysis and area. Video support depends on macOS decoding the file; an extension alone does not establish support.

For a video, use the **Video time** slider or **−1 s / +1 s** controls to choose one frame. Release the slider and wait for the preview to update before analysing. The displayed time returns to the decoded frame's actual presentation timestamp (PTS), which may differ from the requested time. The result describes that one frame only: this workspace does not play the video, analyse audio, summarise events across time or continuously track a subject.

Choose **Select area** and drag a rectangle inside the displayed image when only part of the image or frame is needed. Only the selected crop pixels are sent to the model or OCR. A location returned within the crop is mapped back to the original image for its marker. **Whole frame** removes the selection. Selecting, resetting, seeking or replacing media clears the old result; cancellation waits for the owned work to finish.

Choose **Ask about image**, **Count objects**, **Locate a target**, or **OCR** as appropriate. File analysis uses the selected Apple or MLX model, while OCR uses local text recognition. It does not acquire camera-control permission or turn a marker into a gimbal or autofocus command. Changing the observation source leaves an existing camera connection and its access setting unchanged; Privacy pause remains the way to release capture.

Counts, positions and answers remain model estimates that can be wrong. Wait for a cancelled operation to finish before starting another analysis. The local offline media regression log at `artifacts/offline-media-build23/release-tests-5.log` records 72 tests across six suites passing; it does not establish the actual App smoke test or the complete build 23 release gate.

### Save an immutable result export

After a successful analysis, use **Save Markdown** or **Save JSON** in the **Export result** footer and choose a destination in the save dialog. The footer follows the shared Yun interface styles. Each export is a fixed snapshot of the completed analysis: source basename and type, submitted question and engine, task, answer, evidence and uncertainties, frame metadata, selected-area metadata when used, and result creation time. Video frame metadata records the decoded frame's actual PTS, and a crop retains its original-frame and region information. OCR records the Vision engine and no question.

Exports contain no image or video bytes, source URL, directory path or camera-action claim. They include the source basename and analysis text, which may contain visible personal information; review before sharing. Changing the question or engine after completion does not rewrite the earlier snapshot; run the analysis again for new settings.

### Historical build 22 workspace and evidence

Build 22's actual App smoke test passed Apple questions, MLX counting and location, Vision OCR, cancellation, image replacement and stale-result clearing without a camera. Its offline software/package gate and three-language UI review, benchmark results and public UI-only screenshots remain historical evidence. Those results do not verify build 23's video, area or export additions; the published beta 1 remains build 9.

### Choose observation or framing assistance explicitly

For the camera source, **Observe only** and **Assist framing** now describe the current task separately from standing camera permission. Apple observation no longer starts MLX merely because control permission is already available. Framing assistance can use the downloaded MLX control loop followed by Apple's answer, but only when the existing capability and access checks permit the action. MLX observation likewise receives no movement or zoom tools. No models are downloaded automatically.

CLI `ask --intent observe|assistFraming` defaults to `observe`; Debug `evaluate-workflow` uses the same intent for its simulated camera. These entries do not add an MCP ask wrapper: MCP retains its six basic camera tools. Roles and action results remain distinct; a controller role alone does not prove an adjustment occurred.

The mixed-model hardware record belongs to **build 16**: one raw-200 zoom task completed in 38.039 seconds with 11 checks passing. That historical case is not new build 22 hardware acceptance. The workspace and task routing passed the build 22 offline software, packaged-App and UI checks; build 23's media additions remain pending the actual App smoke test and complete release gate.

### Cancelling zoom now holds the camera's current zoom

Cancelling an in-flight zoom request now waits for a same-connection hold instead of merely clearing the App's moving state while the device continues towards the target. An expired settling deadline uses the same cleanup. A successful hold does not turn the original unfinished zoom into a successful adjustment; an unconfirmed hold blocks further zoom and pan/tilt commands until resolved.

On build 20, a real external MCP cancellation held raw zoom at 200 during a 100→400 request. Independent readbacks stayed stable for 1.090 seconds, without the client sending Stop, and the helper still served its six tools. Timeout cleanup has a deterministic fake-device regression; it has not been induced and verified on the real camera. These readbacks are not calibrated magnification or mechanical braking measurements.

### Active capture can keep working without keeping the display lit

Active capture now holds a scoped macOS activity that prevents idle system sleep. It does not request that the display stay on or change system sleep preferences. Pause, stop, failure and device disconnection release the activity; a new capture session receives its own activity. Explicit system sleep still follows the existing Stop/suspend path.

The activity's acquisition, release and reconnection were checked on the real App while USB preview continued. Physical display-off, locked-session and remote-desktop disconnection behaviour still need separate verification. This remains a logged-in user App, not a service available before login.

### The Yun interface is more consistent across languages

Engine cards, control rows, long MCP paths and settings labels now align more consistently at compact and larger window sizes. Camera and microphone icons align with their labels, and audio feedback and action history use the correct translated descriptions. The earlier camera, engine and settings surfaces received English, Traditional Chinese and Simplified Chinese visual review. Build 22 passed 59 UI captures with layout checks, and its new image workspace was visually reviewed in all three languages with imported images and analysis hidden. Documentation includes complete guides and separately versioned UI-only screenshots without camera photographs.

### Offline development checks

The finite USB validation sequence now ends after an unconfirmed target, hold or return, retaining a partial report. A failed or cancelled report cannot unlock movement. Read-only imported-image diagnostics also gain typed count, point and presence results with range validation; this is an evaluation API, not a completed subject-tracking interface. New hardware validation remains pending.

### Evidence and remaining limits

- Build 22 passed its offline gate at source `dc3595c846fc7d8a45fea6432b9db9f788117fec`: 503 executed tests passed, three opt-in tests were skipped; 59 UI captures, three languages, seven shared Yun files, copied-App MLX/Core AI inference and memory release, offline MCP/CLI intent checks, and ZIP/DMG payload signatures and hashes were checked. Physical camera/audio/movement, published-feed updating and notarisation were not part of this gate.
- The actual App image-workspace smoke test passed Apple questions, MLX count/location, Vision OCR, cancellation and old-result clearing after image/source changes. Camera frames remained zero and its session/access stayed unchanged.
- In the fixed six-image, 18-task typed regression set, Apple passed 12/18 (count 5/6, point 1/6, absence 6/6); MLX passed 14/18 (5/6, 6/6, 3/6). Apple’s host rejections fell to zero after explicit-nil integration; MLX still had three rejections with unavailable raw content. Those cannot be labeled visual hallucinations. This cached, single-repeat test is not a general model ranking. [Recorded build 22 results](https://github.com/YuhuanStudio/Pocket3-Controller/blob/main/Evaluation/Grounding/results/build22-typed.json).
- An isolated, re-signed build 9→17 copy completed actual Sparkle download, installation and relaunch, preserving preferences and producing a fresh IPC session. That test used a separate fixture identity/feed and no camera; it does not establish production-feed updating while capture is active.
- Native quick recenter/flip matching the camera's double/triple joystick press, tap-to-focus and reliable body-setting writes remain unfinished. The full-pair BLE recenter trial submitted its command but observed no motion or matching reply. Readable WB/AF/EV values do not establish that writes work; slow USB movement is not a substitute for native presets.
- UYVY/H.264 preview and 4K60 remain unavailable in the tested paths. An experimental compressed-output diagnostic does not make them usable preview modes. Proven NV12 modes remain the ordinary path; full physical range, speed calibration and experimental Roll are not fully verified.

See the [hardware evidence and limits](https://github.com/YuhuanStudio/Pocket3-Controller/blob/main/docs/HARDWARE_ACCEPTANCE.md) and [release procedure](https://github.com/YuhuanStudio/Pocket3-Controller/blob/main/docs/RELEASE.md) for the scope of each check.

### Installation and updating

Apple Silicon and macOS 27 remain required. The App name, bundle identifier, preferences, local model storage and MCP helper path inside the App remain unchanged. Keep the Mac on its existing network; normal USB control does not require joining the camera's Wi-Fi.

The Beta uses the existing local development signing identity and is **not notarised or Developer ID signed**. First-launch Gatekeeper behaviour on other Macs still requires verification. The signed beta 1 feed is already public; this draft does not publish a beta 2 archive, tag or feed entry. Production beta 1→beta 2 installation through the normal update UI remains a separate release check.

### 相機關閉時使用本機圖片、指定影片影格與區域

build23延伸build22的圖片工作區。選擇 **Media file（媒體檔案）**再按 **Open media（開啟媒體）**，可開啟不超過8 MB的可讀本機靜態圖片，或含視訊軌的本機影片。**Replace media（更換媒體）**會開啟另一檔案，並清除前一次分析與區域。影片是否支援取決於macOS能否解碼，副檔名本身不代表支援。

影片可用 **Video time（影片時間）**滑桿或 **−1 s／+1 s**控制選取一張影格。放開滑桿後等待預覽更新再分析；顯示時間會回到實際解碼影格的呈現時間戳（PTS），可能不同於要求的時間。結果只描述該張影格；工作區不播放影片、不分析音訊、不跨時間總結事件，也不持續追蹤主體。

需要局部分析時，按 **Select area（選取區域）**並在顯示的影像內拖曳矩形。只會把選取區域裁切後的像素送給模型或OCR；裁切區回傳的位置會映回原圖顯示標記。按 **Whole frame（完整畫面）**移除區域。選取、重設、移動影格或更換媒體都會清除舊結果；取消會等待目前工作結束。

按 **Ask about image（圖片問答）**、**Count objects（計算物件）**、**Locate a target（定位目標）**或 **OCR**。檔案分析使用所選Apple或MLX模型，OCR使用本機文字辨識；它不取得相機控制權，位置標記也不會變成雲台或對焦命令。切換觀察來源保留既有相機連線與存取設定；要釋放取像，仍使用「隱私暫停」。數量、位置與回答都是可能出錯的模型估計。離線媒體回歸紀錄 `artifacts/offline-media-build23/release-tests-5.log` 顯示六個測試套件共72項通過；這不是實際App基本流程測試或完整build23發行gate。

### 儲存不可變的分析結果

成功分析後，在 **Export result（匯出結果）**頁尾使用 **Save Markdown（儲存 Markdown）**或 **Save JSON（儲存 JSON）**，再於儲存對話框選擇位置；頁尾沿用Yun共用介面樣式。每份匯出是完成分析的固定快照，包含來源 basename（僅檔名）與類型、送出時的問題與引擎、任務、回答、依據與不確定性、影格中繼資料、使用區域時的區域資料及建立時間。影片影格記錄實際解碼的PTS，裁切保留原始影格與區域資訊；OCR記錄Vision引擎且不含問題。

匯出不含圖片或影片位元組、來源URL、目錄路徑或相機動作宣稱；仍包含來源檔名與分析文字，分享前請先檢視。完成後修改問題或引擎不會改寫先前快照；要取得新設定的結果，需再次分析。

### build22工作區與證據的歷史紀錄

build22曾在真App、無相機條件下通過Apple問答、MLX計數與定位、Vision OCR、取消、換圖及過期結果清除；其離線軟體／打包gate、三語UI檢查、benchmark結果及公開純UI截圖均保留為歷史證據。這些結果不驗證build23新增的影片、區域或匯出功能；公開beta1仍是build9。

### 明確選擇觀察或協助取景

相機來源的 **Observe only（只觀察）**與 **Assist framing（協助取景）**現在代表本次任務，與既有相機權限分開。Apple純觀察不再只因已有控制權就啟動MLX；協助取景可以使用已下載的MLX控制流程，再由Apple回答，但每個動作仍須符合既有能力與權限檢查。MLX純觀察同樣不取得移動或縮放工具，不會自動下載模型。

CLI的 `ask --intent observe|assistFraming` 預設為 `observe`；Debug版 `evaluate-workflow` 的模擬相機使用相同intent。這些入口沒有另加MCP ask wrapper，MCP仍維持六個基礎相機工具。模型角色與實際動作結果分開記錄，控制角色本身不證明做過調整。

混合模型的硬體紀錄屬於 **build16**：一次raw200縮放任務以38.039秒完成、11項檢查通過。這個歷史案例不是build22新增的硬體驗收。新圖片工作區與任務路由已通過build22的離線軟體、打包App與UI檢查；build23媒體功能仍待實際App基本流程測試與完整發行gate。

### 取消縮放會保持相機當前的縮放位置

取消進行中的縮放要求，現在會等待同一連線上的保持操作，不會只清除 App 的移動狀態，讓機身繼續朝原目標前進。等待縮放穩定的期限耗盡時，也會執行相同清理。保持成功不會把原本未完成的縮放算作成功；保持未確認時，後續縮放及 pan/tilt 命令會被阻擋，直到問題解除。

build 20 的真實外部 MCP 測試，在100→400要求途中取消後保持於原始值200，獨立回讀穩定1.090秒，客戶端沒有另送 Stop，helper 仍能提供六個工具。正常逾時清理已有確定性的假裝置回歸測試，尚未在真機上製造並驗證逾時。上述讀回不是已校準倍率或機械煞停量測。

### 持續取像不需要要求螢幕常亮

取像期間現在持有有明確生命週期的 macOS activity，防止系統因閒置而睡眠；不要求顯示器常亮，也不修改系統睡眠偏好。暫停、停止、失敗或裝置斷線會釋放活動，新取像 session 會取得自己的活動。明確的系統睡眠仍走既有 Stop/suspend 流程。

已在真實 App 上核對活動的建立、釋放與重新連接，同時維持 USB 預覽。實際關閉顯示器、鎖定工作階段及遠端桌面斷線仍需分別驗證。App 仍是登入後的使用者程式，不是登入前可用的服務。

### Yun 介面在三種語言中更一致

引擎卡片、控制列、長 MCP 路徑及設定標籤，在精簡與較大視窗中有更一致的對齊。相機與麥克風圖示對齊文字，音訊提示及操作紀錄使用正確的本地化說明。較早的相機、引擎及設定畫面已經英文、繁體中文及簡體中文視覺檢查；build22已完成59份UI擷取與版面檢查，新圖片工作區亦逐張檢視三語畫面，匯入圖片與分析內容均隱去。文件提供完整使用指南與另行標註版本、不含相機照片的純UI截圖。

### 離線開發檢查

有限 USB 驗證序列在目標、保持或返回未確認時立即結束，保留部分報告；失敗或取消不能開啟移動權限。匯入圖片的只讀診斷也加入具型別與範圍驗證的計數、定位、存在性結果；這是評測 API，尚不是完整的主體追蹤介面。新硬體驗收仍待完成。

需要局部分析时，点击 **Select area（选择区域）**并在显示的图像内拖出矩形。只会把选区裁剪后的像素发送给模型或OCR；裁剪区返回的位置会映回原图显示标记。点击 **Whole frame（完整画面）**移除区域。选择、重置、移动视频帧或更换媒体都会清除旧结果；取消会等待当前工作结束。

点击 **Ask about image（图片问答）**、**Count objects（计算对象）**、**Locate a target（定位目标）**或 **OCR**。文件分析使用所选Apple或MLX模型，OCR使用本地文字识别；它不获取相机控制权，位置标记也不会变成云台或对焦命令。切换观察来源保留现有相机连接和访问设置；要释放采集，仍使用“隐私暂停”。数量、位置与回答都是可能出错的模型估计。本地离线媒体回归记录 `artifacts/offline-media-build23/release-tests-5.log` 显示六个测试套件共72项通过；这不是真实App基本流程测试或完整build23发行gate。

### 保存不可变的分析结果

成功分析后，在 **Export result（导出结果）**页脚使用 **Save Markdown（保存 Markdown）**或 **Save JSON（保存 JSON）**，再在保存对话框选择位置；页脚沿用Yun共用界面样式。每份导出是完成分析的固定快照，包含来源 basename（仅文件名）与类型、提交时的问题与引擎、任务、回答、依据与不确定性、帧元数据、使用区域时的区域数据及创建时间。视频帧记录实际解码的PTS，裁剪保留原始帧与区域信息；OCR记录Vision引擎且不含问题。

导出不含图片或视频字节、来源URL、目录路径或相机动作宣称；仍包含来源文件名与分析文字，分享前请先检查。完成后修改问题或引擎不会改写先前快照；要获取新设置的结果，需再次分析。

### build22工作区与证据的历史记录

build22曾在真实App、无相机条件下通过Apple问答、MLX计数与定位、Vision OCR、取消、换图及过期结果清除；其离线软件／打包gate、三语UI检查、benchmark结果及公开纯UI截图均保留为历史证据。这些结果不验证build23新增的视频、区域或导出功能；公开beta1仍是build9。

### 明确选择观察或协助取景

相机来源的 **Observe only（只观察）**与 **Assist framing（协助取景）**现在代表本次任务，与现有相机权限分开。Apple纯观察不再仅因已有控制权就启动MLX；协助取景可以使用已下载的MLX控制流程，再由Apple回答，但每个动作仍须符合现有能力与权限检查。MLX纯观察同样不获取移动或缩放工具，不会自动下载模型。

CLI的 `ask --intent observe|assistFraming` 默认为 `observe`；Debug版 `evaluate-workflow` 的模拟相机使用相同intent。这些入口没有另加MCP ask wrapper，MCP仍维持六个基础相机工具。模型角色与实际动作结果分开记录，控制角色本身不证明做过调整。

混合模型的硬件记录属于 **build16**：一次raw200缩放任务以38.039秒完成、11项检查通过。这个历史案例不是build22新增的硬件验收。新图片工作区与任务路由已通过build22的离线软件、打包App和UI检查；build23媒体功能仍待真实App基本流程测试与完整发行gate。

### 取消缩放会保持相机当前的缩放位置

取消进行中的缩放请求，现在会等待同一连接上的保持操作，不会只清除 App 的移动状态，让机身继续朝原目标前进。等待缩放稳定的期限耗尽时，也会执行相同清理。保持成功不会把原本未完成的缩放算作成功；保持未确认时，后续缩放及 pan/tilt 命令会被阻止，直到问题解除。

build 20 的真实外部 MCP 测试，在100→400请求途中取消后保持于原始值200，独立读回稳定1.090秒，客户端没有另发 Stop，helper 仍能提供六个工具。正常超时清理已有确定性的模拟设备回归测试，尚未在真机上制造并验证超时。上述读回不是已校准倍率或机械刹停测量。

### 持续取像不需要要求屏幕常亮

取像期间现在持有生命周期明确的 macOS activity，防止系统因空闲而睡眠；不要求显示器常亮，也不修改系统睡眠偏好。暂停、停止、失败或设备断开会释放活动，新取像 session 会获取自己的活动。明确的系统睡眠仍走现有 Stop/suspend 流程。

已在真实 App 上核对活动的建立、释放与重新连接，同时维持 USB 预览。实际关闭显示器、锁定会话及远程桌面断线仍需分别验证。App 仍是登录后的用户程序，不是登录前可用的服务。

### Yun 界面在三种语言中更一致

引擎卡片、控制栏、长 MCP 路径及设置标签，在紧凑与较大窗口中有更一致的对齐。相机与麦克风图标对齐文字，音频提示及操作记录使用正确的本地化说明。较早的相机、引擎及设置画面已经英文、繁体中文及简体中文视觉检查；build22已完成59份UI采集与布局检查，新图片工作区也逐张检查了三语画面，导入图片与分析内容均已隐藏。文档提供完整使用指南与单独标注版本、不含相机照片的纯UI截图。

### 离线开发检查

有限 USB 验证序列在目标、保持或返回未确认时立即结束，保留部分报告；失败或取消不能开放移动权限。导入图片的只读诊断也加入具有类型与范围验证的计数、定位、存在性结果；这是评测 API，尚不是完整的主体跟踪界面。新硬件验收仍待完成。
